# CONVENTIONS — mediNix-core Ordnung

Diese Datei ist die **verbindliche Ordnungs-Regel** des Repos. Ziel: **kein
„ein Ordner pro Datei"-Wildwuchs**, sondern vorhersagbare Struktur.

## 1. Ordner-Regel (maschinell geprüft)

> **Ein Ordner existiert erst ab ≥ 3 Dateien.**

**Ausnahmen** (dürfen 1–2 Dateien, weil strukturell *vorgeschrieben*):

| Ausnahme | Warum |
|---|---|
| `NN-…/` (z. B. `51-ingress/`) | Domain-Ordner des Decimal-Frameworks (ADR-0000); `default.nix` **auto-importiert** sie. |
| Ordner mit `default.nix` | Nix-Paket-Layout (Einstiegspunkt + Code) |
| Ordner mit `SKILL.md` | Agent-Skill: pro Skill **ein** Ordner mit `SKILL.md` (+ `references/`). |
| `tests` · `scripts` · `references` · `templates` | Konventions-Orte |
| alles unter `.agents/` · `.github/` · `.git/` | Tooling-/CI-Struktur |

### Prüfen
```bash
# lokal
bash docs/agents/shared/scripts/folder_lint.sh .
```
Läuft zusätzlich in CI (`.github/workflows/order-lint.yml`) — Verstöße brechen den Build.

## 2. Weitere Ordnungs-Regeln

- **Keine losen Skripte im Repo-Root.** Dauerhafte Werkzeuge → `scripts/`
  (bzw. `docs/agents/shared/scripts/`). Wegwerf-Skripte → `scratch/` oder sofort löschen.
- **`*/AGENTS.md` ist generiert.** Nur **oberhalb** von
  `<!-- AUTO-GENERATED, DO NOT EDIT BELOW -->` von Hand editieren.
  Neu erzeugen: `python 50-core/medinix-meta.py generate-docs`
  Prüfen:        `python 50-core/medinix-meta.py check-docs`
- **Dokumentation nach `docs/`**, nicht ins Root (Root = nur Nix-Pflicht
  (`flake.nix`, `default.nix`, `flake.lock`, `repl.nix`, `statix.toml`), die
  Doku-Build-Konfiguration `mkdocs.yml` (sie muss neben `docs/` liegen, weil
  mkdocs ≥ 1.6 `docs_dir` == Konfig-Verzeichnis verbietet) + wenige Meta-Docs
  wie `README.md`, `CHANGELOG.md`, `LICENSE`).
- **Root-Ausnahmen (bewusst dort, mit Begründung):**

  | Datei | Warum im Root |
  |---|---|
  | `AGENTS.md` | Agenten-Verfassung — jeder Agent liest sie im Projekt-Root |
  | `CLAUDE.md` | Zeiger auf `AGENTS.md` (Claude-Code-Konvention) |
  | `ROADMAP.md` | wird von `AGENTS.md`/`CLAUDE.md` per absolutem Pfad referenziert |
  | `opencode.json` | Projekt-Konfiguration des Werkzeugs (muss im Projekt-Root liegen) |
  | `mkdocs.yml` | Doku-Build-Konfiguration (siehe oben) |

  Alles andere gehört nach `docs/`; Altstände nach `docs/audit/<jahr-monat>/`.
- **Keine Build-Artefakte im Repo** (`__pycache__/`, `*.pyc` sind in `.gitignore`).

## 3. Wenn eine Ausnahme doch zu klein wirkt

Nicht flachlegen — **füllen** oder bewusst als Ausnahme dokumentieren. Ordner,
die nur wegen fehlenden Inhalts „spam" sind, gehören gefüllt (z. B. `scripts/`
ist für mehrere Werkzeuge gedacht) oder entfernt.

## 5. Nicht ins Repo (Blacklist)

- Fremdregelwerke/Fremdmanifeste (`.agents/`, `docs/GEMINI.md`) — Agenten-Regeln stehen **nur** in `/AGENTS.md`.
- Flache Zweitfassungen (`docs/SKILL-*.md` neben `docs/agents/<skill>/`, `docs/CHANGELOG.md` als Kopie).
- Code-Dumps in Markdown (z. B. `59-guardrails-export.md`) — Code lebt in `.nix`.
- Archive außerhalb `docs/audit/<jahr-monat>/` oder `docs/archive/`.
- Artefakte (`*.log`, `__pycache__/`, `*.pyc`, `.directory`) — gitignoriert heißt nicht aufgeräumt.
- Handgepflegte Planungslisten (zweite Roadmap) — alles wird aus den Quellen **abgeleitet**.

Maschinenlesbar stehen die Regeln als `AB-0xx` im Korridor
(`.agent-state.json` → `corridor.blacklist`).

## 6. Arbeitsweise — Denken vor Tippen (Methodenwahl & Reflexe)

> **Prosa-Quelle:** `AGENTS.md` §Verifikations-Disziplin (Phasen 1–4). Hier die
> **kurze, prüfbare** Fassung. **Korridor-Index:** `AB-037` (Parser), `AB-038`
> (Zwei-Versuche-Stop). Kein zweiter Ort — nur gespiegelt.

**Vor dem ersten Tastendruck — 3 Fragen schriftlich:**
1. Was ist das für eine Sache? (Datei · Daten · Struktur · Zustand)
2. Welches Werkzeug ist für **diese Klasse** das richtige?
3. Woran merke ich, dass die Methode falsch ist?
→ Unbeantwortbar? **Mehr lesen, nicht mehr tippen.**

**Erst die Klasse, dann das Werkzeug:**

| Klasse | Reflex (falsch) | richtig |
|---|---|---|
| JSON/YAML/TOML ändern | `sed` · `index()` · Concat · f-String | `json.load→dump` · `ruamel.yaml` · `tomlkit` |
| mehrzeilige Logik | Inline-Heredoc | Datei unter `scripts/` |
| Logik in Nix | Regex/Text in `.nix` | Nix-Expression |
| Zustand ändern | Ad-hoc-Kommando | deklarative `.nix`-Datei |
| Version prüfen | `git log` lesen | `git log --format=…` + Parser |

**Zwei-Versuche-Stop (`AB-038`):** Versuch 1 scheitert → Ursache prüfen (kein
Variante-B-Reflex). Versuch 2 scheitert → die **Methode** ist falsch, nicht die
Details → Wurzel klären oder fragen. **Kein dritter Versuch derselben Methode.**

**Beweis-Last:** Nicht „hoffentlich", sondern „funktioniert, **weil X**" — X
**vor** der Mutation zeigen (Roundtrip · `diff` · `--dry-run`). Kein X → mehr
Info, nicht mehr tippen.

**Anti-Muster (Vorzeichen — eines erkannt = STOPP):** Text-Mutation auf
Struktur · Inline-Skript · derselbe Fix erneut · „nur noch eine Kleinigkeit" ·
Erklärung länger als die Aktion · Grund suchen, es *doch* so zu machen.

## ADRs: Formregel (verbindlich)

ID-Schema (SSoT: `docs/adr/llm-index.json` -> `naming`): Dienst-ADR `ADR-<dienstnummer>`
(511, 551, 576) · Meta/Thema `ADR-<domain><slot>` 4-stellig (0000, 0010, 5043, 5050) ·
Fundament reserviert `ADR-00xx`. Datei `ADR-<id-ohne-praefix>-<slug>.md`; Front-Matter `id:`
traegt die ID; Ueberschrift `# ADR-<id>: <Titel>`; jede Datei steht im `llm-index.json`.
Geprueft von `python3 scripts/check_adrs.py` (order-lint): Fehler bei fehlender/doppelter id,
Dateiname != id, fehlender Index-Registrierung; Legacy-Domain-Namen (`ADR-52-*`) und
Slug-ids werden als Kurationsliste ausgegeben.

## Projekt-Skills: Sichtbarkeit per Symlink

Projekt-Skills liegen im Repo (`docs/agents/<kategorie>/<skill>/`). Der Agent findet sie ueber
`~/.config/opencode/skills/<name>` - dort liegen **Symlinks** auf die Repo-Ordner
(`bash scripts/link-skills.sh`, idempotent; `--dry-run` zeigt nur an). Die Symlinks sind
maschinenlokal und werden deshalb nicht versioniert; nach einem frischen Clone einmal ausfuehren.
Die formale Seite (`name` == Ordnername, eindeutig; `description` vorhanden) prueft
`python3 scripts/check_skills.py` in `order-lint`.

Nicht jeder Skill wird verlinkt: `scripts/skills-exclude.txt` schaltet die Sichtbarkeit fuer
Skills ab, die zu fremden Workflows oder anderen Projekten gehoeren (Inhalt bleibt im Repo,
versioniert). Der Linker raeumt ausgeschlossene Symlinks selbst weg.

Offene Nacharbeit: 18 der 29 Projekt-Skills haben eine Trigger-Beschreibung unter 80 Zeichen
(der Check listet sie als Hinweis) - die Beschreibung ist der einzige Trigger, den die Session
ohne Laden sieht.

## Die Kette: sechs Knoten, sieben Kanten

Jede Kante hat entweder einen **Check** oder einen **begruendeten Ausnahme-Eintrag** - beides ist
versioniert, Prosa allein genuegt nicht.

| Kante | Was geprueft wird | Check |
|---|---|---|
| Code -> Manifest | Registry-Dienst mit Port braucht `medinix.manifest.<name>`; kein Manifest-Key ohne Registry-Dienst | `scripts/check_manifest_edge.py` (order-lint), Ausnahmen: `scripts/manifest-edge-allowlist.txt` |
| Code -> ADR | jeder `adr:`-Verweis im Modul-Header zeigt auf eine existierende ADR-ID; ein Verweis auf den DATEINAMEN ist immer ein Fehler | `scripts/check_adrs.py` (order-lint), Altfaelle: `scripts/adr-refs-allowlist.txt` |
| ADR -> Index | Datei steht in `docs/adr/llm-index.json`; id/Dateiname/Ueberschrift passen | `scripts/check_adrs.py` |
| Docs -> Generatoren | `docs/TODO.md`, `docs/INDEX.md`, Ordner-`AGENTS.md` sind aktuell | `scripts/gen_todo.py --check`, `scripts/gen_service_map.py --check`, `50-core/medinix-meta.py check-docs`, `docs/generate_index.py` + `git diff --exit-code` |
| Skills -> Sichtbarkeit | jeder Projekt-Skill hat einen Symlink (bzw. steht bewusst auf der Ausschlussliste) | `scripts/link-skills.sh --dry-run` (lokal), `scripts/check_skills.py` (Form, CI) |
| Skills -> MCP | wer einen Server aufruft (`tools["x"]`/`tools.x.`/`mcp__x`, auch in `references/`), deklariert ihn als `mcp: [x]`; deklarierte Server muessen in `scripts/mcp-servers.txt` stehen | `scripts/check_skills.py` (order-lint) — siehe `docs/MCP-SETUP.md` |
| Korridor -> Checks | Muster der AB-Regeln (DynamicUser, media als Primaergruppe, stateDir-Suffix, hartkodierte uid) sind maschinell geprueft | `scripts/check_corridor.py` (order-lint), Ausnahmen: `scripts/corridor-allowlist.txt` |
| NixOS-Idiome | Klassische-Distro-Reflexe der Schicht 0a (unreine Quellen, Store-Schreibzugriff) | `scripts/nixos_idiom_audit.py --p0-only` (order-lint) |

Regel bei jedem Fund: entweder **fixen** oder eine **Ausnahme mit Begruendung** in die jeweilige
Allowlist/den Korridor eintragen. Allowlist-Eintraege ohne Wirkung melden die Checks selbst
(„stale") - die Listen duerfen nur schrumpfen.
