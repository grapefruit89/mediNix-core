Die vier Module waren **nie verdrahtet** (0 Importeure, in keinem Export referenziert — L-017). Sie sind
kein toter Müll, sondern **vier unbeantwortete Fragen**, jede von einem anderen Typ:

|---|---|---|---|
| `abc-tiering` | „Wie heißen die drei Speicherklassen?“ | ADR-570 (`backends.hot/cold` + MergerFS) | **Vokabular (hoch)** |

| `mk-secure-curl` | „Wie kommt ein Secret in einen Header, ohne in `argv` zu landen?“ | curl-nativ in `513-ddns.nix:171` | **Konvention + Ratsche (hoch)** |

einzeln bewertet. Genau diese Reihenfolge ist die Lehre — nicht das Ergebnis.

## 2. Gefundene Gems (für Scratchboard)

**G-1 · Readiness ≠ `systemctl is-active`.** `wait-for-api` prüft einen *echten API-Endpunkt* mit
Deadline, `[OK]`-Zeile und `FATAL`+`exit 1`. Der Kern ist nicht das Skript, sondern die Unterscheidung
dreier Zustände: Socket offen / HTTP antwortet / API fachlich bereit. Heute in `events.py` sogar besser
gelöst (epoll + `journalctl --follow`, Fail-Fast beim Unit-Crash, 0 % CPU im Wartezustand).
→ **Regel für die Ratschen:** Ein `ExecStartPre`- oder Oneshot-Schritt gegen eine *fremde* API braucht
ein Readiness-Gate; `After=`/`Wants=` ordnen nur Units, sie beweisen keine API-Bereitschaft.

**G-2 · Secret-in-argv ist ein Klassenfehler, kein Einzelfall.** `mk-secure-curl` hat die richtige
Mechanik früh benannt: `--variable secret@<datei>` + `--expand-header "…: {{secret:trim}}"` — curl
expandiert das Secret **intern zur Laufzeit**, `/proc/<pid>/cmdline` bleibt clean. Damit war das Modul
seiner Zeit voraus; L-020 musste einräumen, dass `513` den Token damals noch als
`-H "Authorization: Bearer $TOKEN"` in `argv` legte. Heute steht es korrekt in
`51-ingress/513-ddns.nix:171`. Wert: die **Konvention** (Datei rein, Platzhalter rein, nie `$TOKEN` in `-H`).

**G-3 · Drei Speicherklassen als Vokabular.** `tierA = /var/lib/<svc>`, `tierB = mediaRoot/downloads`,
`tierC = mediaRoot/library` ist als *Code* falsch (siehe A-1), als *Denkfigur* aber genau das, was
ADR-570 heute in Prosa sagt: Tier A = State, Tier B = schnell/vergänglich, Tier C = kalt/Bibliothek,
darüber ein Union-Pfad. Der Zusatz „Tier-Pfade aus `mediaRoot` ableiten (Regel 3: keine hardcodierten
Pfade)“ ist eine Invariante, die man behalten sollte.

**G-4 · `recursiveMergeAttrs` ist *nicht* vollständig redundant.** L-021 verglich es mit `lib.mkMerge`.
Korrekt ist: `mkMerge` konkateniert Listen nur für **Options-Definitionen im Modulsystem**;
`recursiveMergeAttrs` (via `zipAttrsWith`) merged **beliebige Laufzeit-Attrsets** und konkateniert Listen
dort ebenfalls. Für „mehrere JSON-/Config-Fragmente zu einer Datei“ ist das der einzige Weg —
`lib.recursiveUpdate` überschreibt Listen. Als Modul-API überflüssig, als **Merkposten** wertvoll.

**G-5 · Archivieren statt löschen.** `repo-cleanup/` hält den Code, `nixmeta_check.py` überspringt
`docs/audit/` und `docs/archive/`, `git log -- lib/<name>.nix` liefert die Historie. Das ist ein
wiederverwendbares Muster für jede Ausmusterung: **Code raus aus dem Wirkpfad, Wissen bleibt im Repo.**

**G-6 · „Ungenutzt“ ist ein Befund über den Leser, nicht über den Code.** L-017 hat den ersten
Archivierungsversuch widerrufen, weil 0 Importeure nicht „Müll“ heißt, sondern „fehlender Consumer“
(AGENTS §5: *Deklariert ≠ wirkt*). Übertragbar auf jede Lib: ein Export ohne Aufrufer ist eine
**offene DESIGN-Frage**, kein Löschkandidat.

## 3. Erkannte Antipatterns (für Ratschen/Banned)

**A-1 · Konvention als Bibliotheksfunktion (Doppel-Eigentum an einem Pfad).** `abc-tiering` *rechnet*
Pfade nach, die schon als Optionen existieren (`storage.backends.hot/cold`, `mediaRoot`,
`registry.stateDir`, `StateDirectory`). Zwei Quellen für denselben Pfad driften garantiert: `tierA`
ignoriert `StateDirectory`/`RuntimeDirectory` und ist für `DynamicUser`-artige Fälle sofort falsch.
→ **Ratsche:** Pfad nie in einer Lib neu zusammensetzen; Option lesen oder `%S`/`%t`-Specifier der Unit nutzen.

**A-2 · Shell-Kommandos als Strings bauen.** `mk-secure-curl` gibt einen *String* zurück, den der
Aufrufer in `'' … ''` einsetzt. Folge: Quoting wird manuell verteilt (`lib.escapeShellArg` an drei
Stellen, `--expand-header` mit ungeschütztem inneren `"`), Header-Namen sind ungeprüft, nichts ist ohne
Shell testbar, `shellcheck` sieht den Aufruf nie. Richtig wäre eine argv-Liste
(`lib.escapeShellArgs`) oder `writeShellApplication`. → **Ratsche:** generierte Shell nur als
`writeShellScript(Bin)`, nie als frei schwebender String.

**A-3 · Sicherheit als Opt-in-Bibliothek.** Das Muster „es gibt da einen sicheren Helfer“ schützt
nichts, solange der Aufrufer ihn nicht importiert — belegt: das Modul lag ungenutzt da, während `513`
den Token monatelang in `argv` trug (L-020). → **Ratsche statt Helfer:** `grep`-Gate auf
`-H "…Bearer \$`/`-H "X-Api-Key: \$` und `Authorization: Bearer $` in `*.nix`; Verstoß = Check rot.
Sicherheit muss am **Call-Site** erzwungen werden, nicht in `lib/` angeboten.

**A-4 · Busy-Polling mit Sekundenschlaf.** `for ((i=1; i<=timeoutSec; i++)); do … sleep 1; done`
koppelt Intervall und Budget (Timeout = Versuchszahl), pfeift 90 s weiter, wenn die Unit längst
gescheitert ist, hat keinen Backoff und verschluckt mit `2>/dev/null` den Unterschied zwischen
`401`, `ECONNREFUSED` und Timeout — dieselbe Blindheit, die `events.py` ausdrücklich abgeschafft hat.
→ **Banned:** `sleep`-Schleifen als Readiness-Mittel, wenn ein Event-Kanal (journal, sd_notify,
Socket-Activation, `systemd.path`) existiert. systemd-nativ vor selbstgebaut: `Type=notify`,
Socket-Activation, `Restart=on-failure` + `RestartSec`.

**A-5 · Geparkter WIP im Wirkpfad.** `wait-for-api` trug `status: draft` plus „Muster für später“ —
also Code mit Absicht, aber ohne Owner, ohne Task in `todo/tasks.json`, ohne Importeur. Das verletzt
die SSoT-Regel und erzeugt genau die Frage, die dieser Audit beantwortet. → **Ratsche:** `status: draft`
in `lib/` unzulässig; entweder Task-ID im Header oder `docs/audit/`.

**A-6 · Namens-Magie statt Whitelist.** `_helpers` verlässt sich auf einen Unterstrich, damit der
Auto-Import es überspringt — eine Konvention, die nur funktioniert, solange der Import-Mechanismus sie
kennt. Ordnung gehört in eine **explizite Liste**, nicht in einen Dateinamen. `rec { }` mit
Selbstbezug ist dabei unnötig (`let` genügt).
