## 1. Executive Summary

**Evaluiert nicht. Nicht produktionsreif.** Acht der zwölf Module in 53/54/55 enthalten harte Nix-Fehler: ein Syntaxfehler (`536-prowlarr.nix`, eine Klammer zu viel), sieben Fälle von `attribute 'X' already defined` (jedes Modul definiert `systemd.services.<name>` zweimal in derselben Attrmenge), zwei undefinierte Bezeichner (`reg` in `551` und `552`), ein nicht existierender Optionspfad (`554` liest `medinix.services.feishin`), und in **sieben** Modulen wird `cfg.secrets.*` im Service-Scope statt im Root-Scope gelesen (`medinix.sonarr.secrets` existiert nicht). Dazu fehlt `pkgs.seerr` am gepinnten Rev vollständig. Selbst nach Reparatur der Evaluierung ist die Laufzeit unbrauchbar: die *arr-Module verwerfen die `users.users.*`-Hälfte der Service-Factory (Units mit unbekanntem User), Jellyfin/Navidrome/Audiobookshelf/Seerr setzen ihren Registry-Port **nirgends** und lauschen auf ihren Upstream-Defaults auf `0.0.0.0` (Caddy proxyt ins Leere), SABnzbd bekommt über das `python`-Hardening-Profil `IPAddressDeny=any` mit ausschließlich Loopback-Freigabe und kann damit prinzipiell keinen Usenet-Server erreichen — der Killswitch schützt einen Dienst, der ohnehin kein Netz hat. Der Mover prüft `mountpoint` auf keinem der beiden Pfade und legt sein Ziel per `mkdir -p` an: fehlt das Archiv-Mount, schreibt er die Mediathek auf das Root-Dateisystem.

### P0-1 · `cfg.secrets.*` im falschen Scope — 7 Module, garantierter Eval-Abbruch
**Datei/Stelle:** `532-sonarr.nix:21,85` · `533:81` · `534:79` · `535:79` · `536:85` · `541-sabnzbd.nix:21,74` · `551-jellyfin.nix:21,88` · `555-seerr.nix:21,86`
**Zitat** (`532-sonarr.nix`):
```nix
cfg = config.medinix.sonarr;      # Z. 21
...
systemd.services."sonarr" = lib.mkIf (cfg.secrets.sonarrApiKeyFile != null) {   # Z. 85
```
`default.nix` Z. 119–124 definiert unter `medinix.sonarr` ausschließlich `enable`, `package`, `rootFolder`, `qualityProfile`. Die Secrets liegen in `medinix.secrets` (Z. 722 ff.).
**Impact:** `attribute 'secrets' missing`. Der `mkIf`-Prädikatausdruck wird beim Modul-Merge eager ausgewertet — kein Lazy-Schutz. Jedes einzelne dieser Module bricht ab, sobald sein `enable` gesetzt ist. Zusätzlich sind die Ziel-Optionen `types.str` **mit Default** (nie `null`, Z. 728–748), d. h. nach Korrektur des Scopes ist `!= null` eine Tautologie und `LoadCredentialEncrypted` wird unbedingt gesetzt — auf `/var/lib/media-secrets/arr-apikey`, eine Datei, die weder existieren noch `systemd-creds`-verschlüsselt sein muss → Startfehler statt Eval-Fehler.
**Fix:**
```nix

let
  cfg  = config.medinix.sonarr;
  svc  = config.medinix;
  keyFile = svc.secrets.sonarrApiKeyFile;
in
# ... und die Option nullable machen:
# default.nix
sonarrApiKeyFile = lib.mkOption {
  type = lib.types.nullOr lib.types.str;
  default = null;   # NICHT arrApiKeyFile — sonst unbedingtes LoadCredentialEncrypted
};
```

### P0-8 · `python`-Hardening-Profil macht SABnzbd netzwerklos — der Killswitch schützt eine Leiche
**Zitat** — `lib/hardening-profiles.nix:93–96`:
```nix
python = base // {
  MemoryDenyWriteExecute = true;
  PrivateDevices         = true;
} // networkPolicy.loopback;  # nur Loopback — geht durch VPN-ns, kein direktes Internet
```
mit `networkPolicy.loopback = { IPAddressDeny = "any"; IPAddressAllow = [ "127.0.0.1" "::1" ]; };` (Z. 28–31). `541:56` merged genau dieses Profil in die SABnzbd-Unit.
**Impact:** `IPAddressAllow` ist eine eBPF-Filterliste auf Socket-Ebene und wirkt **unabhängig** von Routing und fwmark. SABnzbd kann keinen NNTP-Server auf Port 563 erreichen — weder über `wg0` noch sonstwie. Der gesamte Killswitch aus `526` ist damit gegenstandslos, und der Profilkommentar („geht durch VPN-ns") ist ein Überbleibsel des Network-Namespace-Ansatzes, den ADR-5260 ausdrücklich verworfen hat. Der Dienst startet, lädt nie etwas herunter, und niemand merkt es, weil kein Guardrail den effektiven Netzpfad prüft.
**Fix:**
```nix
# hardening-profiles.nix — eigenes Profil für VPN-konfinierte Python-Dienste
python-confined = base // {
  MemoryDenyWriteExecute = true;
  PrivateDevices         = true;
} // networkPolicy.internet;   # Egress-Kontrolle macht nftables/skuid, nicht IPAddressDeny
# registry.nix: sabnzbd = mkService "sabnzbd" 541 "python-confined" "internal";
```

### P0-12 · `543-mover.nix` — kein `mountpoint`-Check, `mkdir -p` auf das Ziel
**Zitat** (Z. 31–43):
```bash
if [ ! -d "$STAGING" ]; then echo "Mover: stagingDir $STAGING not found — skip"; exit 0; fi
FREE_KB=$(df -Pk "$STAGING" | awk 'NR==2 {print $4}')
…

```
**Impact:** Geprüft wird ausschließlich die **Existenz** von `$STAGING`, nie ob Staging oder Archive gemountet sind. `archiveDir` hat den Default `/data/library` (`default.nix:229–236`), während `570-storage.nix:36–37` nur `/data/media/{movies,series,books,music}`, `/data/downloads`, `/data/cache`, `/data/incomplete` anlegt — `/data/library` ist also weder Verzeichnis noch Mountpoint. Das `RequiresMountsFor` in `unitConfig` (Z. 78) hilft nicht: existiert für den Pfad keine Mount-Unit, löst systemd auf `-.mount` auf und die Bedingung ist immer erfüllt. Zusätzlich ist `pkgs.lsof` als `runtimeInputs` deklariert (Z. 22), wird aber nie aufgerufen — der beabsichtigte „Datei ist noch offen"-Check fehlt, halbfertige `.mkv` über 50 MB werden mitten im Schreibvorgang verschoben.

### P1-3 · `543-mover.nix` — Trigger greift nicht rekursiv, Trigger-Bremse blockiert dauerhaft
**Zitat** (Z. 100–106):
```nix

  wantedBy = [ "paths.target" ];
  pathConfig = {
    PathChanged = cfg.stagingDir;
    # DirectoryNotEmpty removed to prevent trigger loops
  };
};
```
**Impact:** (a) `PathChanged=` auf ein Verzeichnis meldet nur Änderungen an diesem Verzeichnis selbst, nicht in Unterverzeichnissen. SABnzbd und die Arrs legen Downloads in Unterordner (`.../Serie/Staffel/`) — der Mover wird also in genau dem Szenario nie geweckt, für das er gebaut wurde. Sein `find` ist dagegen rekursiv. Bremse ist `StartLimitBurst = 3 / StartLimitIntervalSec = "60"` (Z. 79–80) — nach drei Läufen in 60 Sekunden geht die Unit in `failed` und bleibt dort, bis jemand `systemctl reset-failed` ausführt. Aus einer Schleife wird ein stiller Dauerausfall.
**Fix:**
```nix
pathConfig.PathModified = cfg.stagingDir;   # deckt Schreibvorgänge ab
# und den Selbsttrigger entkoppeln:
serviceConfig.ExecStartPost = "${pkgs.systemd}/bin/systemd-notify --ready";
# besser: Mover-Lauf mit einem Flag im RuntimeDirectory serialisieren
#   und die Path-Unit während des Laufs stoppen (ExecStartPre/ExecStopPost systemctl stop/start …path)
```
